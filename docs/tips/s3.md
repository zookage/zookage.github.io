## Ozone S3 Gateway

Apache Ozone provides S3 compatible APIs. Enable `base/ozone` in `kubernetes/kustomization.yaml` as described in the [Guide](/docs/guide#choose-components), then start the cluster with `./bin/up`. From `client-node-0`, the S3 Gateway is available at `http://ozone-s3g:9878`.

Open the client shell with `./bin/ssh` and run:

```console
zookage@client-node-0:~$ aws s3api --endpoint http://ozone-s3g:9878 create-bucket --bucket test
zookage@client-node-0:~$ aws s3 --endpoint http://ozone-s3g:9878 cp /opt/hadoop/LICENSE.txt s3://test/hadoop-LICENSE.txt
zookage@client-node-0:~$ aws s3 --endpoint http://ozone-s3g:9878 ls s3://test
```

In ZooKage v0.6.0, the client receives the sandbox credentials from the `aws-secret-env` Kubernetes Secret:

```console
zookage@client-node-0:~$ echo $AWS_ACCESS_KEY_ID
zookage
zookage@client-node-0:~$ echo $AWS_SECRET_ACCESS_KEY
zookage-dummy
```

The Secret is defined in [kubernetes/base/common/secret/kustomization.yaml](https://github.com/zookage/zookage/blob/v0.6.0/kubernetes/base/common/secret/kustomization.yaml){:target="_blank"}. The Ozone setup job also registers the secret for the `zookage` user when Kerberos authentication is enabled.

Hadoop S3A uses the same credentials from `kubernetes/base/common/secret/hadoop/s3a.jceks`, mounted at `/run/secrets/zookage/hadoop/s3a.jceks`. To change the shared S3 secret, update `AWS_SECRET_ACCESS_KEY` in the Secret definition and `fs.s3a.secret.key` in `s3a.jceks.properties`, then regenerate the credential store from the ZooKage repository root before restarting the cluster:

```console
$ ./test/jceks create kubernetes/base/common/secret/hadoop/s3a.jceks
```
